## Новые дефекты

- **P2-1.** Диапазон с месяцем после первой даты не распознаётся: «с 30 сентября по 2 октября», «с 12 октября по 18 октября» → разобрано как «с <первая дата>» с `openEnd=true` — верхней границы нет, в сводку попадают сегодняшние пункты, метка `30.09`/`12.10`.
- **P2-2.** Пунктуация внутри фразы не отсекается: «за 3 дня, пожалуйста» → `null` → `ask`; «дай новости за 3 дня, пожалуйста» → `digest` с `periodHint=null` (3 дня теряются); «сводка (за 3 дня)» → `digest` без периода.
- **P2-3.** Период перебивает действия с интересами (порядок FR-4): «покажи интересы за неделю», «за неделю убери робототехнику» → `digest`. Формально по спеке, но действие пользователя теряется — нужен ответ владельца.
- **P2-4.** «интересно, что по золоту» → `interests/add`, `target='что по золоту'`; без LLM `clarifyTerms` пропускает мусор (`length≥3`, не общее слово) → по ✅ в профиль попало бы «что по золоту».
- **P2-5.** `removeInterestTerm`: частичное совпадение подписи удаляет блок целиком — «убери робототехнику» на `«AI и робототехника: новые модели, промпт-инжиниринг»` теряет «новые модели, промпт-инжиниринг» (данные видны в ответе, есть «Вернуть»).
- **P2-6.** `removeInterestTerm` оставляет мусорный остаток: `«Крипта — очень кратко»` минус «крипта» → `«очень кратко»` (новая строка-«интерес»).
- **P2-7.** Термин в двух строках: `«золото\nзолото физическое»` → удаляется только первая, повторный «убери золото» нужен.
- **P2-8.** Закрытые окна фильтруются по `fetchedAt`, не `published`: пункты, собранные этим вызовом, но опубликованные «вчера», в «за вчера» не попадают (eligibility `fetchedAt ≥ from`, затем `fetchedAt < to`) → на первом запросе возможен корректный по коду, но ложный по смыслу ответ «пунктов нет» (U3). Рекомендация: для закрытых окон фильтр по `items.published`.
- **P2-9.** `sendInterests` без чанкования: 120 строк профиля → 7673 симв. (`>4096`), `sendMessage` падает, ошибка гаснет в `send()` — пользователь не увидит ничего (профиль из интервью ≤500 симв. — не воспроизводится).
- **P2-10.** Текст пустого периода: «собрано 3 быстрых источников» (нет `plural()`), `fastCount` — число попытанных, не собранных; пометка `shortHistory` — эвристика по `fetchedAt` (slack 1 день), редкий источник может получить ложную пометку.
- **P2-11.** В контекст ответа по теме (`answerQuestion`) уходит только `fromMs`: `recentItems` без `toMs`, `capped` не сообщается — на «что было по золоту с 1 октября» в контекст попадут и сегодняшние пункты.
