# Требования: интерактивный новостной агрегатор в Telegram

| Поле | Значение |
|---|---|
| Версия | 1.0 |
| Статус | Фаза 0 — планирование. Код не пишется и не запускается |
| Дата | 2026-09-13 |
| План разработки | `docs/plan.md` |

## 1. Назначение продукта

Персональный AI-ассистент новостей в Telegram. Пользователь один раз проходит
интерактивный опрос (при желании добавляет свои источники и настраивает
расписание), дальше бот сам читает все источники и в заданное время присылает
**одно** сообщение — выжимку всего нового с момента предыдущей отправленной
сводки: «как будто личный помощник всё прочитал и сделал выжимку за тебя».

## 2. Контекст и ограничения среды

- Продакшен — тот же MacBook (macOS); деплой и автозапуск — launchd.
- Стек: Python 3, SQLite; aiogram принимается (см. §7, решение D1).
- В репозитории уже существуют `pipeline/` (ранний однопользовательский
  RSS-агрегатор без интерактива), `feeds.txt`, `news.db`, `digests/`, `logs/`.
  Переиспользование существующего кода — только через гипотезы из
  `docs/plan.md` (проверяются на отдельной фазе сверки). `news.db` насильно
  не мигрируется (NFR-07).
- Единственный консьюмер `getUpdates`: ручной запуск бота — только при
  остановленном launchd-агенте, иначе Telegram отвечает 409.

## 3. Приоритеты

- **P0** — MVP, обязательно, end-to-end.
- **P1** — после стабилизации P0.
- **P2** — необязательные улучшения.

## 4. Функциональные требования

Формат записи: **ID · приоритет · название**; «Должно» — что должно быть;
«Проверка» — проверяемый критерий готовности.

### Онбординг и конфигурация

**FR-01 · P0 · Онбординг через FSM-опрос**
Должно: `/start` → приветствие → интерактивный опрос на inline-кнопках:
(1) темы (мультивыбор), (2) предпочтительные источники из подборки каталога
по выбранным темам (мультивыбор, все предвыбраны), (3) частота сводки,
(4) время отправки. Диалог управляется FSM. При 10 минутах неактивности —
осмысленное сообщение о завершении с подсказкой продолжения, состояние
сбрасывается.
Проверка: в новом чате `/start` проходит все шаги и завершается
резюме настроек; молчание >10 мин в середине опроса — бот присылает
сообщение о неактивности, состояние сброшено (следующий ввод не
интерпретируется как ответ на старый вопрос); повторный `/start` начинает
опрос заново.

**FR-02 · P0 · Подбор источников из встроенного каталога**
Должно: по ответам опроса бот добавляет источники из встроенного каталога.
Теги каталога соответствуют приоритетам пользователя: глубоко — драгметаллы
(Au, Pt, Pd), USD/RUB, рынок США, инвест-идеи (вкл. wallstreetbets),
IPO/AI-робототехника/биотех, новые AI-модели, промпт-инжиниринг; кратко —
макро; только направление — геополитика; очень кратко — крипта. Если тем
не выбрано — дефолтный набор по приоритетным темам.
Проверка: выбор единственной темы добавляет только источники с этим тегом;
подобранный набор виден в `/sources`; при нуле выбранных тем набор
не пуст.

**FR-03 · P0 · Повторный опрос в двух режимах**
Должно: из меню можно перезапустить опрос в режимах:
(a) **сброс и замена** — источники, добавленные прошлым опросом
(`origin='survey'`), удаляются, заменяясь новым набором;
(b) **поверх существующих** — новый набор объединяется с текущими
источниками без дублей и без удаления.
Проверка: сценарий (a): после опроса в списке только новый набор +
ручные источники; сценарий (b): список = объединение старого и нового,
дублей нет; ручные (`origin='manual'`) источники сохраняются в обоих
режимах.

### Источники

**FR-04 · P0 · CRUD источников**
Должно: список источников, добавление (мастер: тип → адрес → превью →
подтверждение), удаление, включение/выключение — всё через inline-меню.
Проверка: каждая операция отражается в `/sources` и в последующих сборах;
невалидный адрес даёт понятную ошибку и не ломает состояние диалога.

**FR-05 · P0 · Источник типа RSS**
Должно: пользователь может добавить произвольный RSS/Atom-фид.
Проверка: добавление валидного фида → его элементы появляются в следующей
сводке; невалидный URL/не-XML → ошибка с пояснением.

**FR-06 · P0 · Источник «сайт» (HTML-парсинг)**
Должно: добавление страницы сайта со списком новостей; элементы извлекаются
HTML-парсингом. Неразбираемая страница — ошибка источника, не бота.
Проверка: страница со списком ссылок на статьи приносит элементы;
страница без распознаваемой структуры — статус «ошибка» с сообщением,
бот продолжает работать.

**FR-07 · P0 · Публичный TG-канал через t.me/s/&lt;channel&gt;**
Должно: добавление публичного Telegram-канала, чтение через веб-превью
`t.me/s/<channel>`. MTProto/userbot-доступ **запрещён** (решение D2).
Запросы к t.me — щадящие (последовательные, с паузами).
Проверка: посты канала появляются как элементы сводки; в зависимостях
проекта нет MTProto-библиотек; канал с отключённым превью — понятная
ошибка источника.

**FR-08 · P0 · Subreddit через публичный .json API**
Должно: добавление сабреддита; чтение `https://www.reddit.com/r/<name>/new.json`.
Проверка: посты сабреддита попадают в сводку; при 429 — backoff и
продолжение прогона.

**FR-09 · P0 · Twitter/X через RSS-мост**
Должно: добавление аккаунта X через RSS-мост (шаблон URL в конфиге).
Недоступность моста — **деградация с предупреждением, не блокер**
(решение D3).
Проверка: при работающем мосте твиты появляются в сводке; при
недоступном мосту бот работает, пользователь видит предупреждение
(меню источников / футер сводки), остальные источники собираются.

### Расписание и доставка

**FR-10 · P0 · Настраиваемое расписание**
Должно: частота и время отправки задаются пользователем (в онбординге и
`/settings`).
Проверка: после изменения слота сводка приходит в пределах ±1 минуты от
заданного времени.

**FR-11 · P0 · Сводка покрывает дельту с прошлой отправки**
Должно: окно = [`last_sent_at`, now); при отсутствии прошлой отправки окно =
24 часа (решение D9). Пустая дельта — короткое сообщение «новых новостей
нет» (решение D8).
Проверка: элементы с датами вне окна в сводку не попадают; повторный
прогон без новых элементов шлёт «нового нет», а не пустое сообщение и не
дубль старых пунктов.

**FR-12 · P0 · Догоняющая отправка после сна Mac**
Должно: если слот пропущен из-за сна/выключения Mac, после пробуждения
отправляется одна сводка за всё накопленное окно; дублей нет.
Проверка: остановить бот на 2 слота → запустить: приходит одна сводка
за расширенное окно, `last_sent_at` сдвигается один раз.

**FR-13 · P0 · Формат сводки**
Должно: одно сообщение; стиль личного ассистента; язык — русский; каждый
пункт со ссылкой на первоисточник; при превышении 4000 символов —
разбиение по абзацам, каждое сообщение ≤ 4000.
Проверка: замер длины каждого отправленного сообщения ≤ 4000; в каждом
пункте есть работающая ссылка; текст на русском.

### Управление и UX

**FR-14 · P0 · Главное меню и команды**
Должно: главное меню (inline-кнопки) + команды `/start`, `/sources`,
`/settings`, `/digest`.
Проверка: каждая команда от известного чата отвечает меню или
осмысленным сообщением без ошибок.

**FR-15 · P0 · Индикатор «печатает…»**
Должно: `sendChatAction(typing)` при операциях дольше ~1 с (сбор, LLM).
Проверка: при ручном `/digest` в чате видно «печатает…» до прихода
сообщения.

**FR-16 · P0 · Форматирование Telegram с корректным экранированием**
Должно: HTML (parse_mode=HTML, решение D5) для всего исходящего текста;
все вставки из внешних строк (заголовки, имена каналов) экранируются.
Проверка: заголовки с символами `<`, `>`, `&`, `#`, `_`, `*` отображаются
буквально; в логах нет ошибок Telegram `can't parse entities`.

### P1

**FR-17 · P1 · Telegram Mini App** — *статус 2026-09-14: ОТЛОЖЕНО. Реализация
(И8/М3) вырезана из кода; возврат — отдельная фаза после стабилизации бота.*
Должно: веб-управление источниками и настройками на том же бэкенде; если
невозможно — каркас с fallback на бот-интерфейс.
Проверка: Mini App открывается из меню и выполняет CRUD; при
неработоспособности кнопка ведёт в бот-интерфейс.

**FR-18 · P1 · Несколько пользователей** — *статус 2026-09-14: НЕ ТРЕБУЕТСЯ
(продукт для одного пользователя, D16; `allowed()` это и фиксирует). Возможная
фича после релиза — отдельная задача; схема с `chat_id` готова с итерации 1.*
Должно: изолированные конфигурации (источники, расписание, история) per
chat_id.
Проверка: два тестовых чата — разные наборы источников и расписаний;
сводки не пересекаются.

### P2

**FR-19 · P2 · Кнопка «сводка сейчас»** — *реализовано 2026-09-14 (iter-10):
кнопка меню фиксирует окно как плановая сводка; `/digest` остался предпросмотром.*
Должно: кнопка/команда формирует сводку за текущую дельту и **сдвигает**
`last_sent_at` (в отличие от `/digest`-предпросмотра, решение D10).
Проверка: после «сводки сейчас» плановая сводка не повторяет её
содержимое.

**FR-20 · P2 · Статистика по источникам** — *реализовано 2026-09-14 (iter-10):
`/stats` — собрано за 24 ч и всего per источник.*
Должно: количество элементов per источник за период.
Проверка: `/stats` показывает счётчики, сходящиеся с данными в БД.

## 5. Нефункциональные требования

**NFR-01 · Стек**
Должно: Python 3, SQLite, aiogram; без тяжёлых фреймворков.
Проверка: список зависимостей ограничен решениями D1/D11; нет
Django/FastAPI/Celery и т.п.

**NFR-02 · Изоляция отказов источников**
Должно: отказ одного источника не валит прогон; ошибка пишется в лог
с URL источника.
Проверка: источник с мёртвым URL в наборе → прогон завершается, в логе
запись с URL и исключением.

**NFR-03 · Идемпотентность сбора**
Должно: повторный сбор не создаёт дублей; уникальность по хэшу
URL+заголовок.
Проверка: два подряд прогона сбора → количество строк в `items`
не растёт от повторов.

**NFR-04 · Таймауты и ретраи внешних вызовов**
Должно: каждый внешний вызов (HTTP, LLM, Telegram API) имеет таймаут;
сетевые ошибки/5xx/429 ретраятся с backoff.
Проверка: код-ревью: нет внешних вызовов без таймаута; симуляция
500-ответа → видимая серия ретраев с нарастающей паузой.

**NFR-05 · Секреты и mock-режим**
Должно: ключи в `.env`; без `LLM_API_KEY` / `TELEGRAM_TOKEN` весь цикл
работает end-to-end (mock-сводка; без TG-токена — вывод в stdout).
Проверка: прогон с пустым `.env` проходит все этапы без трейсбэков.

**NFR-06 · Логи и журнал работы**
Должно: логи в `logs/`; `LOG.md` обновляется при каждой итерации.
Проверка: после каждой итерации в `LOG.md` появляется запись, в `logs/`
есть файлы текущего прогона.

**NFR-07 · Нет принудительной миграции news.db**
Должно: новая схема живёт отдельно; переиспользование данных старой БД —
только явным опциональным решением плана.
Проверка: `news.db` не изменяется работающим ботом (проверка по mtime/хэшу
после прогона).

## 6. Сценарии

### 6.1 Happy path

1. `/start` → приветствие → опрос: темы → подборка источников каталога →
   частота → время → резюме настроек.
2. Бот добавляет подобранные источники (`origin='survey'`); пользователь
   может сразу добавить свои: RSS / сайт / TG-канал / subreddit / X-аккаунт.
3. В меню: список источников, добавление, удаление, повторный опрос
   (режимы a/b).
4. В слот расписание → сбор всех включённых источников → дельта с
   `last_sent_at` → LLM → **одно** сообщение-сводка → фиксация
   `last_sent_at`.

### 6.2 Повторный опрос — режим A (сброс и замена)

1. Пользователь выбирает «Пройти опрос заново» → «Заменить».
2. Идёт тот же опрос (темы → источники → частота → время).
3. По завершении: источники прошлого опроса (`origin='survey'`) удаляются,
   добавляется новый набор; ручные (`origin='manual'`) не трогаются;
   `last_sent_at` сохраняется (окно не сбрасывается).

### 6.3 Повторный опрос — режим B (поверх существующих)

1. «Пройти опрос заново» → «Добавить поверх».
2. Тот же опрос.
3. По завершении: новый набор объединяется с текущим (дедуп по
   `UNIQUE(chat_id, kind, url)`); ничего не удаляется.

### 6.4 Деградация Twitter-моста

Мост недоступен (таймауты/5xx после ретраев) → источник получает статус
`degraded`, пользователь видит предупреждение в `/sources` и футер сводки;
сбор остальных источников и расписание продолжаются.

### 6.5 Догоняющая сводка после сна Mac

Mac спал через слот → после пробуждения планировщик видит
`now - last_sent_at > периода` → одна сводка за всё окно → одно
обновление `last_sent_at`.

## 7. Принятые решения

| # | Решение |
|---|---|
| D1 | Фреймворк бота — **aiogram 3.x** (версия фиксируется в зависимостях). |
| D2 | TG-каналы — только через веб-превью `t.me/s/<channel>`; MTProto/userbot **запрещены** (риск бана аккаунта). |
| D3 | Twitter/X — только через RSS-мост (официальный API платный); недоступность моста = деградация с предупреждением, не блокер. |
| D4 | Сводка по расписанию — **одно** сообщение; при превышении лимита — разбиение по абзацам, каждое ≤ 4000 символов. |
| D5 | Форматирование — **HTML** (`parse_mode=HTML`) с экранированием через `html.escape`; MarkdownV2 не используется. |
| D6 | Язык сводки — русский; стиль — личный ассистент; приоритеты глубины тем — как в FR-02. |
| D7 | Пустая дельта — короткое сообщение «новых новостей нет» (не пропуск). |
| D8 | `/digest` — **предпросмотр** дельты: не сдвигает `last_sent_at`. |
| D9 | Первая сводка (нет `last_sent_at`) — окно 24 часа. |
| D10 | «Сводка сейчас» (P2) — сдвигает `last_sent_at` (плановая сводка не повторяет её). |
| D11 | HTTP — aiohttp (уже транзитивная зависимость aiogram); RSS — feedparser; HTML — BeautifulSoup. |
| D12 | Новая схема БД — в отдельном файле (`bot.db`); `news.db` не мигрируется; опциональный одноразовый импорт истории — offline-скриптом, по умолчанию выключен. |
| D13 | Планировщик — **внутри процесса бота** (asyncio); launchd только держит процесс живым (KeepAlive). Календарные launchd-слоты не используются — catch-up обеспечивается логикой по `last_sent_at`. |
| D14 | Сбор источников выполняется в момент отправки сводки (в слот / по команде), отдельного фонового коллектора нет — один код-путь. |
| D15 | Один getUpdates-консьюмер; ручной запуск — только при остановленном launchd-агенте. |
| D16 | P0 — один пользователь; схема БД с `chat_id` везде с первой итерации (готовность к FR-18 без миграций). |
| D17 | Таймаут FSM-неактивности — 10 минут; реализуется sweeper-задачей (проверка раз в ~60 с). |
| D18 | Время/расписание хранятся в UTC, слоты конвертируются по per-user `tz_offset_min` (по умолчанию МСК, +180). |
| D19 | Дедуп элементов — `UNIQUE(source_id, url_hash)`, где `url_hash = sha256(url + '\|' + title)`; в рамках одного источника (для P0-одного пользователя эквивалентно глобальной уникальности). |
| D20 | Секреты в `.env`; без ключей — полный mock-режим end-to-end (mock-сводка: список «заголовок — ссылка», без TG-токена — вывод в stdout). |
| D21 | Каталог источников — статические данные в репозитории; затравка — известные фиды пользователя (гипотеза H5, сверка позже). |
| D22 | Режим A повторного опроса удаляет только `origin='survey'`; ручные источники неприкосновенны в обоих режимах. |
