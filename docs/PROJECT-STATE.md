## 2. Что работает (подтверждено)

- Приём сообщений через вебхук, гейт единственного пользователя (fail-closed), ответы в Telegram.
- Обычная «сводка» — **последние 24 часа** (iter-39). Явный период («за 3 дня», «вчера»,
  «с 12 по 18 октября») по-прежнему до 7 дней. Новости недельной давности в обычную сводку
  не попадают.
- Сбор: до 16 быстрых источников за вызов (у текущего читателя 8 RSS), дедлайн 3 с;
  ещё 2 медленных (каналы через зеркало/html) — после сводки, в следующую.
  Отбор: ≤ 60 пунктов / 120k символов, per-source 8, свежесть по `published`.
- LLM: thinking off, один вызов до 8000 токенов или веер: 2 части по 30 пунктов/5000
  токенов + общий редактор на 2500 токенов, все три параллельно. Живой прогон «за 2 дня»:
  60 пунктов, 5 сообщений, 19 с, 17.1k символов, обрезки нет.
- Обрезка LLM: `LlmTruncatedError` и `.partial` больше не теряются; частичный текст уходит
  с пометкой, при коротком partial — повтор с половиной пунктов (iter-39, P0).
- Период из текста, интересы, дедуп, retention — iter-36/37.
- Два медленных источника (канал/сайт) обрабатываются после отправки сводки, в остаток бюджета.
- JS-тесты: **119/119** зелёные (24.10.2026, `npm test`), включая обрезку и ветки веера.
- `npm run preview` — локальный предпросмотр на `news.db` без Telegram.
- HTML-куски: `sanitizeChunk` срезает оборванный `<` в конце (live-баг «Unclosed start tag»),
  `sendChunk` имеет тот же запас при фолбэке в plain text.

## 3. Что не подтверждено / открыто

- **Python-регрессия локально не прогонялась**: нет зависимостей (`feedparser` и др.).
  По LOG iter-37 — 162 Python-теста. Для проверки нужно окружение с `requirements.txt`
  (venv/Pi/CI).
- **Живой прогон бота из этой сессии не выполнялся** (нет доступа к чату/токену в рамках уборки).
  Последние живые замеры — LOG iter-36/37/38.
- **История `items` из Supabase не перенесена**: на платформе только источники и профиль;
  старые новости в Serverless-версии недоступны (`docs/tgcloud-migration.md` §13).
- Незакрытые срезы паритета (по миграционному документу): онбординг-интервью/FSM,
  часть CRUD источников с пагинацией, ленивый retention-проход, перенос истории.
- Платформенные лимиты: ~30 с wall, ~3 с CPU; нет таймеров, стриминга и `URL`.
  Веер укладывается в 20–22 с на замере, но с полными выжимками вход больше — нужен
  живой замер перед деплоем; при медиане > 26 с снизить до 55 пунктов / 4500 токенов.
- **Retention не удаляет `digests`, `jobs`, `seen_hashes`** — известный долг из аудита
  2026-10-24; при объёме 20k символов на сводку БД растёт быстрее. Отдельная задача.
- `last_sent_at` больше не управляет окном обычной сводки (всегда 24 часа); колонка
  осталась исторической. `getLastSentAt` удалён.
- `GITHUB_*` в `.env` — наследие удалённого воркера, текущим кодом не используются.
