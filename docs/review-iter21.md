## Отложено: требует решения пользователя

| Находка | Почему не в этой итерации |
|---|---|
| Нет индексов `items(fetched_at)`, `digest_items(item_id)`, `items(source_id, published)` | DDL: `CREATE INDEX` в обеих схемах + `_migrate`. Аддитивно и безопасно, но это изменение схемы БД |
| Надгробия `seen_hashes` ключуются `(source_id, url_hash)`, а `source_id` при пере-добавлении/`finalize_survey(replace)` новый → история анти-дубля теряется; каскад `items → digest_items` стирает окно `consumed_keys` | Меняет семантику схемы (ключ `(chat_id, url_hash)` или upsert источников) |
| `scripts/migrate_sqlite_to_pg.py` переносит не все колонки: нет `users.interests_text`, `items.text/enriched/gist`, таблицы `seen_hashes` | Миграция данных |
| `FileHandler run.log` не переоткрывается при ротации; фактический `logrotate` вне репо (проверить `copytruncate`/`postrotate`) | Прод-конфигурация |
| `newsbot.service`: нет `RestartSec`/`StartLimitBurst=0` — при crash-loop systemd гасит юнит насовсем | Прод-конфигурация |
| `rsync` в процедуре деплоя тащит `.env` с Mac на Pi (DEV-токен приоритетнее прод-токена) и идёт без `--delete` (мёртвые модули на Pi) | Прод-процедура |
| Токен, уже попавший в `logs/run.log` и journald, считать скомпрометированным | Перевыпуск через @BotFather — действие пользователя |
| `insert_item`: SELECT по надгробиям + INSERT на каждую запись фида (до ~6k round-trip за цикл через VPN) | Горячий путь сбора; нужен замер RTT, а не догадка |
| `enrich_once`: до 60 последовательных докачек с паузами в одном потоке | Дизайн цикла; паузы — требование вежливости (FR-07) |
| `scheduled_users` вызывается синхронно из event loop каждые 20 с | Требует ревизии общей модели одного коннекта (лок `_LockedConn` только для пула сбора) |
| Выключенный источник (`enabled=0`) продолжает попадать в дайджест своими уже собранными пунктами | Меняет смысл «выключить» (не собирать vs не показывать) |
| `/sources` отдаёт список без учёта лимита 4096 симв. Telegram (падает на большом списке в error) | Мелкий UX-дефект, отдельная итерация |
| Подготовленная за 10 мин сводка не инвалидируется ручной «сводкой сейчас» → возможен дубль в слот | P3, редкий сценарий |
