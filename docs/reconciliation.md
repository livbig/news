## 0. Резюме

План фазы 0 писалcя вслепую и в двух местах ошибся фактическими: (а)
pipeline уже интерактивен (команды, подписки на каналы, LLM-диалог, расписание
внутри процесса) — это не «агрегатор без интерактива»; (б) боевые решения
реальности (IP-пиннинг Telegram, двухфазная подготовка сводки, read-timeout
LLM 900 с, флаг потребления `in_digest` вместо timestamp-окна) доказаны
логом инцидентов и обязаны быть унаследованы, а не переизобретены.
Итог: ~60 % нового бота собирается из существующего кода; главный
операционный риск — 409 getUpdates с живым launchd-агентом — решается
dev-токеном на время разработки и переключением агента в финале (§6).

## 6. Конфликт getUpdates (409) и схема сосуществования

Факт: агент `com.fifth.newsbot` **сейчас работает** (`-m pipeline bot`,
RunAtLoad + KeepAlive) и единолильно держит long-poll `getUpdates` на
прод-токене из `.env`. Любой второй поллер на том же токене — 409.

Схема:

1. **Разработка (итерации 1–6):** у BotFather регистрируется второй
   (dev) бот → `TELEGRAM_TOKEN_DEV` в `.env`. Новый бот стартует только с
   dev-токеном; прод-агент не трогаем — сводные сводки продолжают ходить
   старым ботом, 409 невозможен (токены разные), ручные прогоны нового бота
   безопасны без `bootout`. CI/моки — вообще без токена (NFR-05).
2. **Миграция (итерация 7):** функциональный паритет достигнут (сводки по
   расписанию + каналы + диалог + CRUD) → `launchctl bootout` → в plist
   меняются `ProgramArguments` на `-m bot` (Label `com.fifth.newsbot`
   сохраняется — пользователь не теряет бота) → `bootstrap`. В `.env`
   прод-токен начинает использовать новый бот.
3. **Rollback:** вернуть `ProgramArguments` на `pipeline bot` и
   `kickstart`; код старого бота не удаляется. `pipeline` остаётся CLI
   (`run/digest/check/chatid`) для отладки и на случай отката.
4. **После миграции:** правило AGENTS «bootout перед ручным запуском»
   сохраняется дословно — потребитель по-прежнему один, теперь это новый
   бот.
5. Отклонённые альтернативы: два поллера на одном токене с разбиением
   offset — хрупко и прямо запрещено Telegram; webhook новому + polling
   старому — усложнение без нужды (самоподписанные URL, открытие портов).
