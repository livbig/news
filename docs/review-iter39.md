# Review-loop: iter-39 (объём, веер, окно 24 часа)

Дата: 2026-10-24. Ревью кода после реализации подходов 2 и 3.
Проверки: `npm test` (119/119), `node --check` всех модулей, `git diff --check`,
локальные прогоны `scripts/preview-digest.mjs` на реальных заголовках `news.db`.

## What this change does

Обычная «сводка» теперь всегда за последние 24 часа и берёт до 80 пунктов вместо 25.
Если пунктов ≥40, три LLM-вызова идут параллельно: две части пишут разделы, третья —
общий лид, синтез и радар. Один вызов остаётся для коротких сводок (<40 пунктов) и умеет
отдавать частичный текст при обрезке. Заодно удалены мёртвые экспорты и обновлены
AGENTS/README/PROJECT-STATE/migration/LOG.

## Must fix — найдено и исправлено в ревью

1. **Обрезка LLM теряла частичный текст** (`tgcloud/lib/llm-core.js:200`)
   - **What this is:** `call()` бросает `LlmTruncatedError` с `.partial`, когда модель
     упёрлась в `max_tokens`. `summarizeWith()` ловил её и перебрасывал обычный `LlmError`.
   - **Problem:** имя ошибки и `.partial` терялись; восстановление в `message.js` не срабатывало.
     Проверено mock-SSE: `name=Error`, `partial=""`.
   - **Fix:** `if (lastError instanceof LlmTruncatedError) throw lastError;`, плюс `name`
     в конструкторах. Тест в `tests/js/llm.test.js`.
   - **If we skip it:** при 5000–8000 токенах пользователь получал бы «Сводка не удалась»
     вместо обрезанной сводки.

2. **Тексты обещали «с прошлой сводки» и 7 дней** (`digest.js:368`, `render.js:9,24`,
   `message.js:61`)
   - **What this is:** после перехода на 24 часа `EMPTY_TEXT`, help, settings и подсказка
     `/start` всё ещё говорили о прошлой сводке и неделе.
   - **Problem:** пользователь просит «сводку», получает пусто и читает ложную причину.
   - **Fix:** тексты переписаны на «последние сутки»; явный период — до 7 дней.
   - **If we skip it:** недоверие к боту и лишние запросы.

3. **Редактор веера говорил «за сутки» для явного периода** (`prompts.js:91`)
   - **What this is:** `FANOUT_EDITOR_PREFIX` был захардкожен «Ниже весь поток за сутки».
   - **Problem:** на «сводка за 3 дня» лид говорил бы «за сутки», а заголовок — «за 3 дня».
   - **Fix:** «за запрошенный период».
   - **If we skip it:** противоречие в одном сообщении.

4. **Пункты упавшей части помечались прочитанными** (`digest-run.js:82`)
   - **What this is:** при успешном редакторе `items` возвращал все `selected`, даже если
     одна из частей упала.
   - **Problem:** пункты упавшей части не попадали в текст деталей, но больше не приходили.
   - **Fix:** `items` — только пункты успешных частей; они вернутся в следующую сводку.
     Тест обновлён: 5 пунктов, а не 10.
   - **If we skip it:** тихая потеря половины новостей при сбое одной части.

5. **JSDoc `emptyPeriodText` приклеился к `splitIntoParts`** (`digest.js:399`)
   - **What this is:** новый helper вставлен между комментарием и функцией.
   - **Problem:** читатель ищет описание пустого периода у чужой функции.
   - **Fix:** комментарий перенесён к `emptyPeriodText`.
   - **If we skip it:** ложная документация в самом читаемом месте.

6. **LLM-текст не тримился** (`llm-core.js:194`)
   - **What this is:** ответ начинался с `\n`, `composeDigest` давал лишнюю пустую строку.
   - **Problem:** визуальный мусор в начале каждого сообщения.
   - **Fix:** `normalizeLlmText(text).trim()`, partial тоже trim.
   - **If we skip it:** косметика, но заметная на каждом выпуске.

7. **CI не запускал JS-тесты** (`.github/workflows/tests.yml`)
   - **What this is:** workflow гонял только Python.
   - **Problem:** регрессия в `tgcloud/` проходила CI зелёной.
   - **Fix:** добавлены `actions/setup-node@v4`, `npm install`, `npm test`.
   - **If we skip it:** прод-код без CI.

## Should fix — открытые, не блокируют этот выпуск

8. **Retention не удаляет `digests`, `jobs`, `seen_hashes`** (`store.js:339-361`)
   - **What this is:** удаляются только `items` старше 10 дней и `chat_history` старше 30.
   - **Problem:** одна сводка теперь 11–23k символов; `digests.messageText` растёт без границы.
   - **Fix:** отдельная задача: удалять `digests`/`digest_items`/`jobs` старше 30 дней,
     `seen_hashes` старше 40; `onConflictDoNothing` для надгробий.
   - **If we skip it:** БД растёт быстрее, но на одного пользователя запас ещё есть.

9. **`insertItem` — check-then-insert** (`store.js:192-220`)
   - **What this is:** `SELECT` дубля, потом `INSERT`; уникальный индекс
     `(source_id, url_hash)`.
   - **Problem:** две одновременные инвокации могут получить `UNIQUE constraint failed`
     и пометить источник `error`.
   - **Fix:** `onConflictDoNothing` и проверка `rowsAffected`.
   - **If we skip it:** редкие «источник упал» при пересечении запросов.

10. **Дубли разделов между частями веера** (`digest-run.js`)
    - **What this is:** части делятся по порядку пунктов, а не по темам; «Геополитика»
      и «AI» могут встретиться в обеих.
    - **Problem:** читатель видит два одноимённых раздела.
    - **Fix:** части подписаны «ЧАСТЬ 1/2», это принято как компромисс ради объёма.
      Если раздражает — вернуться к темам-кнопкам (подход 1) или классифицировать пункты.
    - **If we skip it:** структура чуть менее чистая, но ничего не теряется.

11. **Модельные огрехи в тексте** (`preview-2026-10-24T09-38-06`):
    «внова» вместо «снова», «Сanders» в одном из прогонов, редкие low-value пункты
    в «ПРОЧЕЕ». Это не код: промпт уже требует отбрасывать шум и давать вывод.
    Добавлен user-префикс «каждый пункт — суть и вывод, не просто заголовок»; стало лучше,
    но 100% гарантии нет.

12. **Частичная отправка чанков** (`message.js:240-250`)
    - **What this is:** если Telegram отклонил середину, `recordDigest` не вызывается.
    - **Problem:** при следующем запросе уже отправленная часть может повториться.
    - **Fix:** отдельная задача — ретрай чанка или запись «частично доставлено».
    - **If we skip it:** редкие дубли при сбое Telegram.

13. **`sourcesView` показывает 8 источников без пагинации** (`sources-ui.js:29`)
    - **What this is:** остальные видны текстом, но кнопок нет.
    - **Problem:** при 20–100 источниках нельзя выключить/удалить дальние.
    - **Fix:** `perPage` 20 или `src:page:<n>`.
    - **If we skip it:** управление источниками неполное.

14. **Неизвестный `kind` (reddit) молча `ok`** (`collect.js:63-68`)
    - **What this is:** `collectOne` возвращает `{added:0}` для любого неизвестного типа.
    - **Problem:** мёртвый источник числится здоровым.
    - **Fix:** `UNSUPPORTED` или Reddit через RSS; убрать из README (уже убрано).
    - **If we skip it:** статистика врёт.

15. **Секреты внутри публичного пути** (`tgcloud/lib/secrets.js`)
    - **What this is:** файл в `.gitignore`, но лежит внутри `tgcloud/`, который входит
      в orphan-снапшот.
    - **Problem:** сборка снапшота копированием может опубликовать токены.
    - **Fix:** проверка `git check-ignore` + grep перед пушем (добавлено в AGENTS §7).
    - **If we skip it:** риск утечки бота и ключа LLM.

## Live verification (revision 54, 2026-10-24)

- Приложение `app8766943850`, вебхук in sync, 14 источников в БД.
- `сводка за 2 дня`: **60 пунктов, 5 сообщений, 19 с**, текст 17.1k символов, обрезки нет.
- Первый `сводка` после деплоя: 29 пунктов, 3 сообщения, 18 с; пул 24 ч был частично
  выбран предыдущими тестами. Это следствие нескольких прогонов подряд, а не ошибка.
- Live-баг: модель отдала оборванный `<` перед «СИНТЕЗ»; Telegram вернул
  «Unclosed start tag» и кусок не ушёл HTML-ом. Исправлено: `sanitizeChunk` срезает
  недописанный тег, `sendChunk` — тот же запас в plain-фолбэке. Тест в `text.test.js`.
- 80 пунктов при 5000 токенах дали обрезку одной части; production cap снижен до 60
  (2×30), после чего live-прогон прошёл без обрезки.
- Каналы через зеркало: два параллельных запроса ловили HTTP 429; оставлен
  последовательный сбор, каналы и html идут после сводки по два за вызов.
- Визуал: заголовок → лид → объединённые разделы → «СИНТЕЗ» → «НА РАДАРЕ»;
  5 чанков ≤ 4000, запрещённых тегов нет. `mergeSections` склеивает одинаковые
  разделы двух частей и убирает метки «ЧАСТЬ 1/2», чтобы не было дублей.

## Verdict

Первый default-прогон после деплоя дал 29 пунктов, потому что пул 24 ч был выбран
тестовыми запросами; при обычном режиме «раз в сутки» пул будет полным.

(~130 строк); зависимостей не добавлено.
