# Требования: семантика запросов — период и интересы (iter-26)

Статус: черновик для разработчика и тестировщика; код не трогаем до ответов на §7.

> больше не двигается, отбор до 80 пунктов и веер. Ниже — срез на 2026-10-19.

Факты о платформе — `docs/tgcloud-migration.md` §11 (один вызов = один ответ, ~30 с wall, нет `setTimeout`/`process.env`).

## 1. Проблема и цель

«Короткая» сводка логична: окно = [`last_sent_at`, now), а всё отправленное ранее вычитается через `consumedKeys`/`seen_hashes`, поэтому повторный запрос в тот же день отдаёт почти пусто. При этом попросить период словами нельзя: `intents.js` уже распознаёт «за неделю» и отдаёт `windowHint`, но `handlers/message.js` его игнорирует. Второй пробел: интересы (`users.interests_text`) правятся только вручную, источник «по интересу» не создаётся.
Цель: из свободного текста понимать (а) за какой период нужна сводка и (б) какие интересы добавить/убрать, — предсказуемо и без потери содержимого при повторных запросах.

## 2. Use cases

| # | Фраза пользователя | Ожидаемое поведение |
|---|---|---|
| U1 | «какие новости за неделю» | сводка за [now−7д, now), шапка с датами, дедуп прошлых сводок НЕ применяется |
| U2 | «сводка за 3 дня» | окно 72 ч; повтор через час — те же пункты, новая строка `digests` |
| U3 | «а что было вчера» | окно [вчера 00:00 MSK, сегодня 00:00 MSK) |
| U4 | «сводка по золоту» | это ВОПРОС по ленте, не сводка: ответ LLM со ссылками |
| U5 | «мне интересно было бы углубиться в physical ai и робототехнику» | предложение с 2 терминами и 2 источниками Google News, кнопки «Добавить»/«Отмена»; запись только по кнопке |
| U6 | «убери робототехнику» | термин уходит из профиля, его источники (`origin='interest'`) удаляются, кнопка «Вернуть» |
| U7 | «покажи мои интересы» | список терминов и число источников по ним; БД не меняется |

| U9 | «убери криптовалюты» (такого нет) | «такого интереса нет» + список текущих; БД без изменений |

## 3. Функциональные требования

**FR-1 · P0 · Разбор периода из свободного текста.**
Формулировки: «за неделю / за 2 недели / за 3 дня / за сутки / за месяц» (цифрой и словом), «за последние N дней»,
«за сегодня / за вчера / за позавчера», «с понедельника / со вторника / с прошлой пятницы», «с 3 октября», «с 03.10»,
«с 1 по 5 октября», «за всё время / с самого начала».
Границы: конец = `now`; для «за вчера» и «с A по B» конец = 00:00 MSK дня после B; «за N дней» = [now − N·24ч, now); «за сегодня» = [00:00 MSK сегодня, now); «с <дата>/<день недели>» = [00:00 MSK этого дня, now); год — текущий, если дата в будущем — предыдущий. Часовой пояс — `users.tz_offset_min` (180), не константа в коде.
Проверка: юнит-тест `parsePeriod` на ≥10 фразах; «за 3 дня» → `fromMs = now−72ч ± 60с`.

**FR-2 · P0 · Явный период и дедупликация (ключевое).**
При явном периоде `selectPending` получает пустые `consumedUrls`/`consumedTitles` — уже отправленное не вычитается, поэтому повторный «за неделю» отдаёт то же содержимое. Отбор детерминирован (`published DESC, id DESC`, лимиты те же) ⇒ одинаковый период при неизменной БД даёт тот же `set(digest_items.item_id)`. Сводка за период пишется в `digests`/`digest_items` (нужно для анти-дедупа неявных сводок), но `users.last_sent_at` НЕ обновляется — якорь неявного окна не двигается. Пункты живут 10 дней (retention), период ≤7 дней покрыт гарантированно.

**FR-3 · P0 · Шапка и честные пометки.**
Шапка — `periodHeader(from, to, tzOffsetMin)` от явного периода. Дополнительно: если набор совпал с `digest_items` последней сводки — строка «ℹ️ Это те же пункты, что в сводке от ДД.ММ ЧЧ:ММ»; при усечении периода — пометка об усечении (FR-4); при неполной истории источников — пометка о неполноте.

**FR-4 · P0 · Приоритет интентов (детерминированно, без LLM).**
Порядок: (1) `/digest` → неявное окно; (2) период в тексте → сводка за период;
(3) действие с интересами («добавь / убери / покажи / углубиться / больше про») → управление интересами;
(4) тема («по золоту», «про ставку») → вопрос по ленте (`ask`, окно ≤7 дней, контекст `recentItems`); (5) иначе — `ask`.
«Сводка по золоту за неделю» = вопрос по теме (тема приоритетнее периода для выбора действия), окно уходит в контекст; фильтра по теме в отборе нет. Период >7 дней и «за всё время» — усечение до `windowDays` (7) + пометка «окно ограничено 7 днями».

**FR-5 · P0 · Добавление интереса естественным языком.**
Триггеры: «мне интересно…», «добавь в интересы…», «углубиться в X», «хочу больше про X», «следи за X». Термины извлекаются LLM-сервисным вызовом (`thinking` выкл., `serviceMaxTokens`), ≤3 термина, ответ — JSON-массив; при недоступной LLM — детерминированный фолбэк (слова после маркера, ≤3 фразы) с пометкой «(LLM недоступна, взял формулировку как есть)».
Запись — только после подтверждения кнопкой: «Добавить в интересы: 1) … 2) … Источники: Google News по каждому. [✅ Добавить] [❌ Отмена]»; состояние в `fsm` (`state='await_interest'`, `data={terms}`, TTL 10 мин), callback_data `int:add` / `int:cancel`.
Запись: термины дописываются в конец `users.interests_text` по одному в строке; дедуп нормализованный (lowercase, ё→е, trim). Лимит 4000 символов — при превышении отказ «профиль заполнен — сначала убери что-нибудь», запись не выполняется.

**FR-6 · P0 · Удаление интереса.**
Триггеры: «убери X», «удали из интересов X», «больше не интересно X». Сопоставление по нормализованному вхождению. Нет совпадений → «такого интереса нет» + список текущих, БД без изменений. Несколько совпадений → уточнение кнопками (≤5), запись до выбора не делается.
Удаление: строка из `users.interests_text` + источники с `origin='interest'` и `topics`, содержащим термин, — через `store.deleteSource` (вместе с их `items` и `seen_hashes`). Ответ: «🗑 Убрал: X (источников удалено: N)» + кнопка «↩️ Вернуть» (снимок в `fsm`, 10 мин), восстанавливающая профиль и источники.

**FR-7 · P0 · Просмотр интересов.**
«покажи мои интересы» / «что у меня в интересах» / `/interests` → нумерованный список терминов, для каждого — есть ли активный источник; если профиль пуст — «профиль не задан, в сводке используется дефолтный» (поведение сводки не меняется).

**FR-8 · P0 · Источники по интересу.**
1 термин = 1 источник `kind='rss'`,
`url = https://news.google.com/rss/search?q=<encodeURIComponent(term)>&hl=ru&gl=RU&ceid=RU:ru`,
`title='Google News: <term>'`, `origin='interest'`, `topics=[term]`, `enabled=1`. Не больше 3 новых источников за одно подтверждение. При `sources.max` (100): интерес записывается, источники не создаются, пользователю сказано об этом. Существующий URL не дублируется (`uniq_sources_chat_kind_url`). Ручное удаление источника в `/sources` интерес не удаляет; повторное добавление того же интереса источники не пересоздаёт («уже в интересах, источник смотри в /sources»).

**FR-9 · P0 · Бюджет вызова.**
Управление интересами сбор не запускает: ответ ≤8 с (включая LLM-извлечение), все чтения/записи — в одном вызове.
Сводка за период делит бюджет как обычная: сбор быстрых источников ≤5 с (≤16, курсор-ротация), LLM `thinking=false`,
`maxTokens=3000`; при остатке <20 с — tight-режим (10 пунктов / 12000 симв.). Медленные источники (каналы/`html`) при сводке за период не собираются — их пункты уйдут в следующую, в сводке пометка. Не хватило времени на LLM — честная ошибка (FR-13), пункты не теряются. Статус-сообщение содержит период: «🔎 Собираю за 3 дня…».

**FR-10 · P0 · Идемпотентность и откат.**
Повторное добавление существующего термина → «уже в интересах», `interests_text` и `sources` байт-в-байт те же. «Убери» несуществующего → без изменений. Двойное нажатие «✅ Добавить» → второе отвечает «уже добавлено» без дублей (`fsm` очищается после первого применения). Повторная сводка за период → новая строка `digests`, `last_sent_at` не двигается.

**FR-11 · P0 · Пустой результат.**
Неявное окно пусто → текст + подсказка: «Новых с прошлой сводки нет. Можно попросить «сводка за неделю» — покажу всё за 7 дней». Явный период пуст → «За период ДД.ММ–ДД.ММ пунктов нет (собрано N источников, ошибок M)». Пометки об ошибках источников — как сейчас (`degradedFooter`).

**FR-12 · P0 · Неоднозначность.**
Больше 3 терминов в одном сообщении, термин короче 3 символов или общего вида («новости», «технологии») → переспрос вариантами, запись не выполняется.

**FR-13 · P0 · Деградация LLM.**
Сводка — как сейчас (⚠️ с причиной, без mock). Интересы: извлечение — фолбэк FR-5; просмотр и удаление — вообще без LLM. Отказ LLM никогда не приводит к записи в `users.interests_text` без подтверждения.

**FR-14 · P1 · Тексты и команды.**
`helpText`/`settingsText` получают примеры фраз периода и интересов; в `COMMANDS` добавляется `interests`. Формулировки русские, без «правильных команд».

## 4. Краевые случаи

| Случай | Ответ |
|---|---|
| период >7 дней / «за всё время» | усечение до 7 дней + пометка в шапке |
| начало периода в будущем («за 2027-01-01») | «этот период ещё не начался», `digests` не пишется |
| «с 1 по 5» без месяца | текущий месяц; конец в будущем — усечение до `now` |
| период без пунктов | FR-11, без пустого сообщения |
| профиль интересов пуст | сводка использует `DEFAULT_INTERESTS`; «покажи интересы» это сообщает |
| термин уже в профиле, источника нет | «уже в интересах» + предложение добавить источник в `/sources` |
| лимит `sources.max` | интерес пишется, источники нет, сказано явно |
| LLM недоступна | FR-13 |
| платформа убила вызов | `jobs.status='failed'`, текст об ошибке; частичная доставка — «доставлено не полностью» |

## 5. Критерии приёмки (проверяемые)

1. `route('какие новости за неделю').kind === 'digest'`, `windowHint` разобран в `fromMs = now − 7·24ч ± 60с` (`tests/js/intents.test.js`).
2. «сводка за 3 дня»: новая строка `digests` с `period_from ≈ now−72ч`, `users.last_sent_at` не изменился.
3. Повтор «сводка за 3 дня» через 5 минут: `set(digest_items.item_id)` совпадает, строк `digests` на 1 больше.
4. «сводка» после явной: окно по `last_sent_at`, пункты явной сводки исключены.
5. «а что было вчера»: `period_from` = 00:00 MSK вчера, `period_to` = 00:00 MSK сегодня.
6. «сводка за месяц»: окно 7 дней + текст пометки об усечении.
7. «сводка по золоту» → `kind === 'ask'`, ответ содержит ссылку из ленты.
8. «мне интересно было бы углубиться в physical ai и робототехнику»: до нажатия кнопки `interests_text` не изменился; после — содержит 2 термина, в `sources` появились 2 строки с `origin='interest'` и `url LIKE 'https://news.google.com/rss/search?q=%'`.
9. Повтор фразы из п.8: `interests_text` и число строк `sources` не изменились.
10. «убери робототехнику»: термина нет в `interests_text`, строки `sources` с этим `topics` и их `items`/`seen_hashes` удалены; «↩️ Вернуть» восстанавливает профиль и источники.
11. «убери криптовалюты» (нет такого): `interests_text` идентичен до/после, `sources` не изменился.
12. «покажи мои интересы» и «отмени»: сообщение корректно, БД не меняется, `fsm` без `await_interest`.
13. `npm test` (`tests/js/*.test.js`) зелёный; новые тесты — `intents`, `period`, `interests` (парсинг, лимит 4000, дедуп).
14. Живой прогон: «сводка за 3 дня» ≤27 с, «добавь интерес» ≤8 с.

## 6. Не-цели

Веб-поиск и полнотекстовая выдача вместо Google News RSS; автосоздание источников без подтверждения; глубина больше 7 дней (меняет решение 2026-10-19 и retention); веса и приоритеты интересов; правка `SYSTEM_PROMPT` дайджеста; замена существующих источников на Google News; расписание и пуши; мультипользовательность; Mini App.
